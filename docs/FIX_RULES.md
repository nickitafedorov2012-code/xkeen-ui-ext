# ПРАВИЛА (перечитывать командой `bash scripts/fix_gate.sh rules`)

Ты исправляешь баги из `docs/BUG_AUDIT.md` по одному. Эти правила важнее твоего желания закончить быстро.

## Запрещено всегда
1. `git commit`, `git push`, `git stash`, `git reset`, `git checkout -- <файл>`, `git restore`, `git clean`. Существующие незакоммиченные изменения не откатывать и не перезаписывать; при необходимости дополнять те же файлы, сохраняя эти изменения и проверяя diff.
2. Деплой, `ssh`, `scp`, любые запросы на 192.168.2.1, сборка под роутер. Смена любых паролей.
3. Править `scripts/fix_gate.sh`, `docs/FIX_RULES.md`, `docs/FIX_PROMPT.md`, текст пунктов в `docs/BUG_AUDIT.md`, любые файлы в `docs/fix_logs/`.
4. Удалять, ослаблять, помечать `#[ignore]`/`.skip`/`.only` существующие тесты. `#[allow(...)]`, `@ts-ignore`, `as any`, `todo!()`, `unimplemented!()`, `assert!(true)`.
5. Писать «исправлено», «готово», «тесты проходят», если в этом же ответе нет вывода `=== GATE OK bug N ...` от шлюза.

## Обязательно для КАЖДОГО бага (без пропусков, без объединения шагов)
6. `bash scripts/fix_gate.sh rules` — перед началом бага.
7. Найти код по ИМЕНИ функции (`grep -n`), а не по номеру строки из аудита — строки могли сдвинуться. Показать реальные строки командой `sed -n 'A,Bp' файл`. Описание бага сверять с показанным кодом, а не с памятью.
8. Несовпадение одной цитаты с аудитом не доказывает отсутствия проблемы: проверь весь сценарий. `NOT_REPRODUCED` — только с доказательствами; при недостатке данных `BLOCKED`.
9. Сначала тест, потом исправление, если это возможно. Тест вызывает настоящий рабочий код и проверяет описанное поведение. Для уже исправленного пункта следуй процедуре `already` из уточнений промпта.
10. `bash scripts/fix_gate.sh red N <spec>` — проверь, что тест действительно упал из-за неверного поведения. Ошибка компиляции или среды не доказывает RED, даже если шлюз её принял.
11. Минимальное исправление первопричины. Не заглушка, не `if test`, не спецслучай под тест, не try/catch, глотающий ошибку.
12. `bash scripts/fix_gate.sh green N <spec>` — пока нет `GATE OK`, баг НЕ исправлен. Падает чужой тест → чинить код, а не тест.
13. Запись в `docs/FIX_LEDGER.md` по шаблону. Пустых полей нет.

## Инварианты проекта (нарушил = новый баг)
- Строго два канала трафика: Direct + (БС ИЛИ VPS). Никакого третьего.
- Запись config.yaml только через ConfigTx; порядок локов config_lock → routing_lock.
- Цели правил Mihomo — только группы и DIRECT/REJECT, не ноды подписок.
- Фон не затирает настройки пользователя; UI не шлёт полный старый снимок.
- iptables: `-w`, идемпотентно, есть парная очистка. AdGuard вкл ⇔ редирект 53→порт AGH.
- Без лишних сбросов соединений всей сети. Секреты не уходят в логи, Telegram, URL, GET-ответы.
- Порты, пути, имена групп — из конфига, не хардкод. Zero-Touch: пользователю не нужно ничего делать руками.
- Без блокирующего CDN-скана при сохранении доменов.

## Перечитывать правила
- после каждого сообщения пользователя и сжатия контекста;
- перед каждым новым багом и не реже каждых двух минут активной работы; проверять время между вызовами инструментов;
- после каждых 10 вызовов инструментов;
- перед каждым `green`;
- всегда, когда хочется написать «готово», «в целом», «аналогично», «остальное по тому же принципу».

Если сомневаешься — не угадывай. Статус `BLOCKED` с конкретной причиной лучше, чем красивая ложь.
