# Аудит панели — 2026-09-28

## Статус

Аудит: приблизительно 25% согласованного объёма. Это оценка охвата, не гарантия отсутствия ошибок.
Три пакета: изменения/снижение риска по 4 из 10 первичных находок (40%); backend не проверен исполнением. Этот процент не означает полного закрытия дефектов.

## Первый пакет изменений

- Zapret UI: dirty-черновики config/hosts защищены от polling, пустые серверные строки допускаются. Редактирование блокируется на время сохранения. Два новых компонентных теста.
- Failsafe: аварийный обработчик вызывает удаление правил без отмены собственного процесса. Добавлена структурная Rust-проверка; она НЕ заменяет исполнение shell на Linux.
- Hostlist: предыдущие community-блоки удаляются перед повторной генерацией. Добавлен Rust-тест повторного применения и удаления старых блоков.

## Открытые риски / технический долг

1. CRITICAL (снижение риска, не полная реализация): test_dpi и mini-blockcheck отключены с HTTP 503 вместо синтетических результатов. Требуется реальная диагностика клиентского пути; Rust-ответ ещё не проверен исполнением.
2. CRITICAL: установка Zapret смешивает mutable-источники, общий /tmp и рабочую установку; нет проверяемого атомарного переключения.
3. CRITICAL: start/stop и NDM-hooks не имеют общей сериализации полного перехода состояния.
4. CRITICAL: обязательные ошибки сохранения/reload игнорируются, состояние RAM расходится с диском и процессом.
5. CRITICAL: перенаправление клиентского DNS не проверяет готовность целевого DNS-сервиса.
6. MAJOR: загрузка community-list не ограничивает размер ответа; дедупликация O(N²); требуется политика адресов и редиректов.
7. MAJOR: save_config несимметрично обновляет SMART_TV_MODE и исключения устройств; версия установки захардкожена.
8. MAJOR: polling не защищён полностью от устаревших ответов; после сохранения старый ответ ещё может перезаписать snapshot. Dirty-защита решает только потерю текущего ввода.
9. MAJOR: повреждённые маркеры hostlist требуют отдельного fail-closed разбора, чтобы не терять ручные строки.
10. MAJOR: API-монолит объединяет HTTP, shell, установку, routing, persistence и диагностику.

## Второй пакет изменений

- ConfigTx: снимки YAML/JSON/extra-files теперь допускают отсутствие только при NotFound. PermissionDenied, InvalidData и прочие ошибки прерывают подготовку до записи. Добавлены три Rust-теста; исполнение не проверено из-за отсутствия toolchain.
- Исправлено двойное потребление Result в существующем Rust-тесте YAML.
- Общий frontend API-клиент: HTTP 401/403/500/503 больше не принимаются за успех при success=true в теле; флаг success должен быть строго true. До исправления 7 из 8 новых сценариев падали.
- Полный откат ConfigTx ещё НЕ исправлен: необходимо возвращать результаты восстановления, учитывать отмену future и сохранять блокировки до завершения восстановления runtime.

## Дополнительные находки ConfigTx

Файл backend/src/transaction.rs:

- Снимки begin/set_extra_file: дефект смешения отсутствия файла и ошибки чтения исправлен во втором пакете; Rust-тесты добавлены, но не запускались.
- rollback (317–350): ошибки восстановления и reload подавляются; вызывающий код сообщает об откате без подтверждения его успеха.
- Drop (378+): синхронные неатомарные записи на async-worker; восстановление файлов не равнозначно восстановлению конфигурации работающего Mihomo.
- files_applied выставляется только после всех записей (292): отмена future между записями требует отдельного анализа и fault-injection теста.

Не создавать второй дублирующий ConfigTx. Сначала определить гарантии снимков, отмены, фиксации и отката; затем адаптировать координацию Zapret, учитывая внешние shell-hooks.
