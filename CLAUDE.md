# Rules for Claude Code & AI Agents (XKeen Route)

## 1. Обязательное чтение перед стартом
Перед любым действием, анализом или правкой кода **ОБЯЗАТЕЛЬНО** открой и прочитай целиком:
- `AGENTS.md` и `GEMINI.md` (все железные правила проекта)
- `docs/REWORK_FIRST.md` (обязательный порядок работы с багами и проверками)
- `docs/HANDOFF_STATE.md` (живой чекпоинт текущей эстафеты между нейронками)

## 2. Непрерывная эстафета между нейронками при исчерпании лимитов (`docs/HANDOFF_STATE.md` + триггер «продолжай»)
Так как над проектом работают разные нейронки, модели и аккаунты, а лимиты (квоты) могут закончиться внезапно посреди хода, ты **ОБЯЗАН** вести файл `docs/HANDOFF_STATE.md` по принципу Write-Ahead Log:
1. **ПЕРЕД** изменением любого файла запиши в `docs/HANDOFF_STATE.md` текущий шаг со статусом `[IN_PROGRESS]`, список затрагиваемых файлов, функции и цель правок.
2. **СРАЗУ ПОСЛЕ** завершения микро-шага и проверки обнови статус в `docs/HANDOFF_STATE.md` на `[DONE]` и укажи следующий шаг в `[NEXT]`.
3. **ТРИГГЕР «ПРОДОЛЖАЙ»**: Если пользователь пишет слово **«продолжай»** (или ты запущен после падения лимитов предыдущей нейронки) — прочитай `AGENTS.md`, `docs/HANDOFF_STATE.md`, выполни `git status` и `git diff` и молча подхвати незавершённый шаг `[IN_PROGRESS]` ровно с той же строчки кода.
4. **ТРИГГЕР «ДАЙ»**: Если пользователь пишет слово **«дай»** — обнови `docs/HANDOFF_STATE.md` и выдай готовый структурированный промпт для переноса контекста в новый чат.

## 3. Координация роя до 20 агентов и правила рефакторинга
- **1 пишущий агент = 1 изолированный файл**: Категорически запрещено двум агентам редактировать один и тот же файл одновременно.
- **Защита от BSOD при сборке**: Воркерам запрещено запускать параллельно 20 процессов `cargo test` / `npm run build`. Полный прогон тестов делает только один выделенный агент `@gatekeeper`.
- **Неприкосновенность поведения**: При структурном рефакторинге внешние контракты API (`/api/*`), структура `config.json`/`config.yaml`, CSS и `data-testid` не должны меняться.
- **Режим «Записывай и жди команды»**: Без прямой команды пользователя («приступай», «делай», «продолжай») не меняй файлы и не запускай сборки.
