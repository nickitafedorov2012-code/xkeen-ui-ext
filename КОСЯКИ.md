### Косяк: `csqtt-client` не вшит по умолчанию и падает при скачивании с GitHub (`direct`)

* **Симптом:** При попытке установить/включить VK-туннель на роутере без доступа к GitHub (или при неработающем/незапущенном прокси) падает ошибка: `Не удалось скачать компонент: Не удалось скачать (direct): сетевая ошибка: error sending request for url (https://github.com/nickitafedorov2012-code/xkeen-ui-ext/releases/download/csqtt-core-0e90df2/csqtt-client-linux-arm64)`.
* **Причина:** В `backend/src/vkturn/health.rs` (`install_core`) и `backend/src/vkturn/mod.rs` (`CORE_RELEASES`/`CORE_TAG`) компонент `csqtt-client-linux-arm64` (~10.3 МБ) не вшит в бинарник/пакет по умолчанию и скачивается только с одного URL на `github.com` без запасных зеркал.
* **Открытый вопрос пользователю:** Как лучше исправить?
  1. Вшить `csqtt-client-linux-arm64` прямо в `xkeen-route-arm64-v8a` (или в архив установщика), чтобы распаковывался в `/opt/sbin/csqtt-client` офлайн «из коробки» (плюс ~10.3 МБ к бинарнику/пакету).
  2. Или оставить скачивание по требованию, но добавить RU-зеркала / fallback-источники и загрузку через ПК/панель.

### Косяк: Ошибка «не входит ни в одну переключаемую группу» при выборе серверов из `🛡️ Whitelist` / `geodema` (чат `748b7bdb`)

* **Симптом:** При клике на сервер (например, `🇩🇪 Обход [Cooper] - Германия`) панель возвращает ошибку: `Сервер '...' не входит ни в одну переключаемую группу`.
* **Причина:** В `backend/src/mihomo.rs` функция `select_groups_to_switch` намеренно исключает группу `🛡️ Whitelist` из списка переключаемых групп, а в `switch_server_inner` переключение `🛡️ Whitelist` засунуто внутрь `if switched > 0`. Если подписки нет в `PROXY` (в `config.yaml` у `PROXY` было только `use: [vkturn]` без `geodema`), переключение падает с ошибкой.
* **Статус:** Временно обойдено только в конфиге на роутере `192.168.1.1` (ручное добавление `geodema` в `use:` группы `PROXY`), **в коде `backend/src/mihomo.rs` не исправлено**.

### Косяк: Пинг `0` у всех серверов при недоступном прямом DNS (`1.1.1.1` / `8.8.8.8`) (чат `748b7bdb`)

* **Симптом:** Все серверы (включая `geodema` и `📞 VK-туннель [БС]`) показывают задержку `0` (`get delay: all proxies timeout`), хотя сам туннель живой (`http://1.1.1.1/generate_204` отвечает `188` мс).
* **Причина:** `health_check_url` задан как `http://www.gstatic.com/generate_204`, а в `dns.nameserver` в `/opt/etc/mihomo/config.yaml` указаны только `1.1.1.1` и `8.8.8.8`. На мобильном канале / при блокировке прямого DNS до `1.1.1.1` Mihomo не может отрезолвить `www.gstatic.com` и ставит всем узлам `delay: 0`.
* **Статус:** **Не исправлено** (нужен рабочий fallback DNS/DoH или IP-check в `health_check_url`).

### Косяк: VK-туннель (`csqtt-client`): зависание в `phase: "authorizing"` на `turn_transport: "tcp"` и обрыв TLS при MTU 900 (чат `748b7bdb`)

* **Симптом:**
  1. При переключении на `turn_transport: "tcp"` VK-туннель зависает в `phase: "authorizing"`.
  2. При тесте HTTPS через `csq0` (MTU 900) наблюдался обрыв TLS (`unexpected eof while reading`).
* **Статус:** **Не исправлено** (дополнительно: фикс `commit_vkturn` в `backend/src/vkturn/tunnel.rs` для добавления `vkturn` в `use:` группы `PROXY` и `MATCH,PROXY` внесён в локальный код, но ещё **не залит бинарником на роутер и не закоммичен**).
